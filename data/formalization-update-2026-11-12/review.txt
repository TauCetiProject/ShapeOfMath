PROMPTS AND SPECIFICATION LESSONS

prompts/update-formalization-coverage.md is the public operational workflow, linked from prompts/README.md and formalization.md. An unqualified update request defaults to the whole active catalogue in Mathlib and Tau Ceti; a narrower user request overrides that default. The workflow freezes an explicit roster, pins upstream/dependencies, delegates all mathematics to subagents, requires independent review, saves complete native file sets through audited operations, measures the reviewed commit, checks shared allocations, exports, and verifies webpages.

Concrete refinements added during this pass:
- Enumerate native namespace directories and adjacent API before inherited classification; dependency availability alone does not establish absence of native contributions.
- Compare actual hypotheses, conventions, normalizations, generated/generic representations, and proof bodies. Familiar names and filename positions do not decide mathematical identity.
- Check every material clause, including equivalences, uniqueness, realization, asymptotic/quantitative assertions and algorithmic cost. Preserve missing clauses as partial/unknown instead of silently dropping them.
- Verify domain hypotheses for totalized integrals/divisions/limits and exact measurability/topology/regularity conventions.
- Separate direct API on the defining object from formulas about prerequisite inputs. Ordinary weaker-hypothesis laws may qualify after explicit instantiation; input-only refinements do not.
- State supplied inputs for generic representations and avoid assuming away a material existence/comparison theorem.
- Treat conjecture statement coverage explicitly as statement-only, in data, exports, UI and aggregates.
- Version concurrent concept changes and re-review the current paragraph; retain old baseline/proposal/review artifacts.
- Record later discoveries as separate independently reviewed corrections, preserving original imported history.

REMAINING SPECIFICATION LIMITS

The current status field combines mathematical availability extent with native contribution ownership. A checked dependency-only partial implementation has no dedicated status: with no qualifying native file, this pass records unknown/empty files, explains the checked covered component and supplier, and names the unresolved endpoint. This must not be confused with an unsearched concept. A future schema could separate extent from ownership; no such migration was introduced during this pass.

Endpoint-by-endpoint scope and named-versus-generic representation provenance remain free-text evidence. statement_only is computed from conjecture kind, not an independent proof-state audit. Whole-file allocation depends on catalogue mapping density. These limitations and the independent prompt review are retained in prompt-review.json.
