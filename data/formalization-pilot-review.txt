SPECIFICATION AND PROMPT CHANGES

1. Added inherited availability as a distinct status. It requires actual dependency declaration/proof evidence at the pinned dependency commit, no native files, and zero native LOC. Unknown or absent formalization is not inferred from native-file absence.
2. Native core API may extend a dependency-defined concept. Attribute the definition to the dependency and count only the project-owned API files. Never charge an import-only wrapper or copied dependency paths to the importing library.
3. Require a declared bounded core API selection and representative declaration anchors. Availability completeness is separate from API-inventory breadth. Equivalent forms, ordinary identities, universal properties, equality cases and natural maps qualify; independently significant endpoints, extra structures and applications do not qualify merely through use or proximity.
4. Added formalization measure --revision COMMIT; it reads those exact Git blobs, ignoring a different HEAD and local edits. This was exercised against both real repositories in a disposable database and independently verified against every selected snapshot file.
5. Tightened semantic comparison: generated additive APIs and proved converse inverse axioms count; filename labels do not determine roles; CS real-part/norm formulations match the complex statement; absolute-Galois-group presentation equivalence does not imply equivalence of ambient fixed-field assertions.
